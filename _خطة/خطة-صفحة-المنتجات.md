# صفحة «المنتجات» · Build Brief

**What this page is:** the paid-ad destination. Custom Elementor page (`/products/`), not the WooCommerce archive. `/shop/` stays the full archive and receives the handoff. Mobile first, 375px is the design width. Target total mobile height **2500 to 3500px** (Nyka Mania is 9626px and puts its first buyable product 5278px down at 375px, which is 6.5 phone screens; that is the failure this page exists to avoid).

**Global rules for the page:** no countdown, no stock counter, no `لفترة محدودة`, no free‑shipping progress bar, no percentage discount, no star row, no instalment logos. Every price on the page comes from WooCommerce, never typed into HTML. Zero `href="#"` ships.

## 4 · THE RAIL — SETTLED

**Auto-advance: NO.** Drag only on mobile and touch, and none on desktop by default.

**The honest grounds.** Baymard is unconditional: *"never auto-rotate on mobile websites or for touch devices"* — with no hover there is no pause, and a slide that moves mid-tap sends her to the wrong product page, on the page paid traffic lands on. NN/g 2013: a participant hunting Siemens washing-machine deals missed a £100 cashback that was the biggest item on the page in both screen space and font size, because a 5-second rotation left it visible ~20% of the time — *"I didn't have time to read it. It keeps flashing too quickly."*

**What we must NOT claim.** "Auto-rotation reduces clicks" is not supported. Runyon's one auto-rotating site had his **highest** click rate (8.8% vs 1.7 to 2.3% static). The defensible claim is narrower: on touch, auto-advance risks mistaps and hides content, and its benefit is unproven for a small catalogue. Do not put any of these figures in site copy.

**Settings.**

| | Value |
|---|---|
| Dwell | **none** — no `setInterval`, no timer, anywhere in the component |
| Card width | `78vw`, max `320px` |
| Gap | `12px` |
| Peek at 375px | next card **clipped by ~50px** (≈17% of a card) — a cut card, not a shadow or a fade; NN/g's illusion-of-continuity cue is the only strong carousel signifier their research names |
| Snap | `scroll-snap-type: inline mandatory`, `scroll-snap-align: start`, `scroll-padding-inline-start: 20px` |
| Controls | **both**, and neither alone: labelled **chips** carrying package names (Mobify: thumbnails ~2× more used than any other control, 6 taps deep vs 3.5 for swipe, which was the *least* used control even on mobile) + **arrow buttons at real touch size** with a visible count. Anonymous dots are weak signifiers; use named chips instead. |
| Arrows shown | when `matchMedia('(hover:hover) and (pointer:fine)')`, or always when the rail overflows — never overlaid on artwork |
| Tiny-catalogue guard | `scrollWidth <= clientWidth` → hide chips and arrows, render as `.luvit-card-grid` |
| Pause rules | n/a, nothing moves by itself |
| `prefers-reduced-motion: reduce` | reuse `LUVIT_REDUCED` (motion.js:52, do not re-query): arrow and chip jumps use `scroll-behavior:auto` instead of `smooth` |
| Overscroll | `overscroll-behavior-inline: contain`; gutters on both sides so the swipe never starts at the screen edge where the browser back gesture lives — and that edge **flips** between LTR and RTL |
| RTL | read `getComputedStyle(el).direction`, **never** the `dir` attribute (trap 2, 9 Aug). All offsets in logical properties. Do not read the sign or magnitude of `scrollLeft` — engines disagree in RTL. Flip the arrow's `scrollBy` sign from the computed direction, and mirror the glyphs. |
| Verify | at 375 and 1200: `document.scrollWidth === document.clientWidth`, `scrollTo(±4000,0)` inert. The tokens.css 5.26.2 invariant currently asserts *"no element declares overflow-x auto/scroll"* — reword to "no element **outside the rail**" and **re-run the check**, do not assume it. |

**If Ryan insists on movement anyway,** the only regionally attested version is the **banner or strip**, not the cards (Beauty Box ships a real `<button class="slideshow__autoplay" aria-label="Pause slideshow">`, three dots, 5s). If it must be the package cards, all four ship in the same commit or none do: gate on `(hover:hover) and (pointer:fine)` — never viewport width, never user agent, or a touch laptop gets unpausable rotation, the exact case Baymard forbids; interval **6000ms**; pause on hover; permanent stop after any interaction; plus a visible pause control and no timer under reduced motion. **A full-width strip showing one card at a time that moves itself is a hero carousel in a rail costume, whatever the file calls it.**
