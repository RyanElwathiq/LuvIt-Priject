## ١) القرار المعماري: وين بتنكتب الطبقة

**القرار: امتداد لـ`tokens.css` نفسه، قسم جديد واحد بآخر الملف تماماً (بعد السطر 3484، بعد `.luvit-quiz` اللي حالياً آخر شي)، بعنوان `/* ===== WOO COMPAT v2 (Phase 5) ===== */`.**

الأسباب، وكلها من قيود المشروع نفسها:

1. **النشر سنيبت WPCode واحد.** ما في خيار "ملف ثاني" أصلاً؛ الدليل بيقول "paste the entire contents". أي قسم منفصل بيعني سنيبت ثاني وترتيب تحميل جديد لازم ينفحص، بلا فائدة.
2. **قاعدة "الأخير بيفوز" لازم تشتغل معنا.** عند تساوي التخصيص، اللي بآخر الملف بيدهس. آخر الملف هو المكان الوحيد اللي بيضمن إن قواعد التوافق بتغلب أي تعريف سابق بالمكتبة عند التعادل (فخ ٩ آب رقم ٤).
3. **الطبقة القديمة (سطر 2190 لـ 2265) بتضل بمكانها بلا لمس.** هي شغّالة وبتخدم فورمات `/my-account` الكلاسيكية (`.woocommerce form .form-row`) وCartFlows. نقلها = إعادة ترتيب قواعد مفحوصة بلا داعي. اللي بيتعدل فيها بس تعليقان:
   - تعليق السطر 1647 ("at the end of this") صار كاذباً، يتصحح ليشير إن في طبقتين: "legacy compat at ~2190, WOO COMPAT v2 at end of file".
   - تعليق بأول الطبقة القديمة: "Classic-form compat. Blocks cart/checkout live in WOO COMPAT v2 at the end of this file."
4. **البنية الداخلية للقسم الجديد خمسة أجزاء مرقمة** عشان أي جلسة لاحقة تلاقي مكان التوسيع فوراً:

```
/* 5.0 SHARED: box-sizing scope, page backgrounds, navbar fix, notices */
/* 5.1 SHOP (/shop, classic loop) */
/* 5.2 ACCOUNT (/my-account, classic) */
/* 5.3 CART (blocks React, CSS only) */
/* 5.4 CHECKOUT (blocks React, CSS only) */
```

5. **طبقة متغيرات صغيرة بأول القسم** (المبدأ الثلاثي من design-system: primitive ثم semantic ثم component). المكونات الجديدة ما بتشوف hex أبداً:

```css
:root {
  /* WOO COMPAT component tokens · بيستهلكوا توكنز المكتبة الموجودة بس */
  --woo-card-gap-mobile:  var(--space-4);
  --woo-card-gap-desktop: var(--space-5);
  --woo-table-head-bg:    var(--color-mist);
  --woo-nav-tab-bg:       var(--aqua-50);
  --woo-nav-tab-active:   var(--aqua-100);
  --woo-page-bg:          var(--color-canvas);
}
```

6. **قاعدة التخصيص بكل القسم:** scope بغلاف الصفحة + مضاعفة كلاس على العنصر الهدف (`.x.x`). `!important` ممنوع إلا إذا الكور نفسه حاطط وحدة، وساعتها بتتوثق بتعليق فوقها مباشرة.
7. **`box-sizing` بيتصرح صراحة** بأول 5.0، لأنه مش مضمون على ماركب ووكومرس (فخ ٩ آب رقم ٦):

```css
.woocommerce, .woocommerce *,
.woocommerce *::before, .woocommerce *::after,
.wc-block-cart, .wc-block-cart *,
.wc-block-checkout, .wc-block-checkout * {
  box-sizing: border-box;
}
```

8. **ميزانية الزجاج بصفحات ووكومرس: صفر عناصر `backdrop-filter` جديدة.** الصفحات دي وظيفية (شراء)، والزجاج الوحيد فيها هو النافبار الموجود أصلاً. ولا `.luvit-card--glass` ولا بلور على أي بطاقة أو مودال.

#### مخاطر الحزمة ج

1. **ما في معاينة محلية للبلوكات إطلاقاً.** React بيرندر على الموقع بس. الفحص كله من داخل الموقع الحقيقي (ريّان بيصور، أو معاينة من لوحة ووردبريس).
2. **تحديثات ووكومرس ممكن تغير كلاسات البلوكات.** الكلاسات المستعملة كلها من الجرد الفعلي (✅) وهي المستقرة تاريخياً، بس بعد أي تحديث Woo كبير الصفحتين بينفحصوا.
3. **دمج LiteSpeed للـCSS ممكن يغير الترتيب.** عشان هيك الضمانة تخصيص (scope + مضاعفة = 0,3,x فما فوق) مش ترتيب.
4. فخ الاتجاه: البلوكات بتاخد `direction` من لغة الووردبريس؛ ولا قاعدة عنا بتقرأ خاصية `dir`، وكل الخصائص المكانية logical (`inset-inline-start` وأخواتها).

## ٣) حل النافبار الأبيض على الأبيض (قسم 5.0)

صفحات ووكومرس ما بتحمل `data-nav-bg`، فالنافبار بيفتح بوضعه الافتراضي (المصمم لهيرو غامق) على خلفية بيضاء. نقطة الإمساك الوحيدة المضمونة بلا تعديل صفحات: **body classes** اللي ووردبريس بيطبعها لحاله.

```css
/* 5.0 · Woo pages have no data-nav-bg: force the on-light nav state.
   Same values as .luvit-nav.is-on-light (tokens.css ~1113-1260). */
body.woocommerce-page .luvit-nav.luvit-nav,
body.woocommerce-shop .luvit-nav.luvit-nav,
body.woocommerce-cart .luvit-nav.luvit-nav,
body.woocommerce-checkout .luvit-nav.luvit-nav,
body.woocommerce-account .luvit-nav.luvit-nav {
  background-color: rgba(255, 255, 255, 0.72);
  border-color: rgba(12, 51, 60, 0.10);
  box-shadow:
    inset 0 1px 0 rgba(255, 255, 255, 0.90),
    inset 0 0 0 1px rgba(12, 51, 60, 0.05),
    0 14px 30px -18px rgba(12, 51, 60, 0.45);
}
/* وألوان روابط/أيقونات النافبار بهالحالة: نفس قواعد .is-on-light الموجودة،
   تتنسخ بنفس البلوك (تتقرا من قسم النافبار وقت التنفيذ · القيم عند 1113-1260) */

/* وخلفية الصفحة نفسها عشان الشبكة ما تسبح على أبيض صريح */
body.woocommerce-page, body.woocommerce-cart,
body.woocommerce-checkout, body.woocommerce-account {
  background: var(--woo-page-bg);            /* canvas #FAFCFD */
}
```

**نقطتا فحص إلزاميتان قبل اعتباره خالصاً:**
1. `document.body.className` بكونسول كل صفحة من الأربعة، للتأكد إن الكلاسات فعلاً موجودة (هي 📘 موثقة، بس التحقق ثانيتان).
2. **هل `motion.js` بيكتب ستايلات inline على النافبار عند السكرول؟** إذا بيكتب `style.backgroundColor` مباشرة، الـCSS مهما تضاعف ما بيغلب inline، وساعتها الحل بيصير تعديل صغير بـ`motion.js` (فولباك: إذا ما في `data-nav-bg` بالصفحة، ضيف كلاس `is-on-light`). هاد بينفحص بقراءة `motion.js` بأول جلسة تنفيذ، وأي تعديل JS بيمر على ريّان لأنه بيعني إعادة لصق سنيبت الفوتر كمان.

## ٤) قرارات لازم ترجع لريّان (ما تنحسم بالتنفيذ)

1. **الـwaterline على شبكة المتجر:** ماركب ووكومرس ما فيه غلاف صورة، فتوقيع الموجة إما ينشال من بطاقات المتجر (البديل: رفعة + زوم بس)، أو ننفذه بسودو تقريبي على رابط المنتج مع مخاطرة شكلية. التوصية: بلاه بالنسخة الأولى، بس القرار إله.
2. **نسبة قص صور المنتجات:** إعداد Customizer → WooCommerce → Product Images لازم يتظبط على 4:5 ليطابق `--card-media-ratio`، وهاد إعداد لوحة هو بيعمله (وبيحتاج Regenerate thumbnails إذا الصور مرفوعة من قبل). سؤال صريح: شو الإعداد الحالي؟
3. **المنطقة والرمز البريدي بالشيك أوت:** شيلهم الصح من إعدادات ووكومرس (أو فلتر PHP بسنيبت WPCode منفصل). مين بينفذ وأي طريقة؟ بند مستقل مش CSS.
4. **نصوص الشيك أوت (CRO):** نص زر الإتمام ("اطلبي الآن والدفع عند الاستلام" بدل الافتراضي)، وسطر الثقة جنب الزر، وشرح حقل الهاتف ("للتواصل عند التوصيل"). النصوص جاهزة كاقتراحات بس بتنشر بموافقته (خطه الأحمر: كل نص بيراجعه).
5. **صفحة المنتج المفردة (single product):** مش بالجرد ولا بهاي الخطة. جوّا نطاق مرحلة ٥ ولا مرحلة لحالها؟
6. **فورمات الدخول/التسجيل:** لقط ماركبها بده جلسة خروج من الموقع. مين بيعملها ومتى (هو بيتصفح logged-out ويصدّر، ولا منستنى)؟
7. **طلب تجريبي:** فحص جدول الطلبات والشيك أوت الكامل بده طلب COD حقيقي تجريبي وبعدين حذفه/إلغاؤه من اللوحة. موافق؟
8. **CartFlows:** الطبقة القديمة بتغطي حقوله. في فنلات منوية قبل الإطلاق فعلاً؟ إذا لأ، ولا سطر جديد إله بهاي المرحلة.
9. **تعديل `motion.js` إذا طلع بيكتب inline على النافبار** (بند ٣ فوق): موافقة مسبقة إنه إذا انكشف هاد، منعدل الـJS ومنعيد لصق سنيبت الفوتر.
